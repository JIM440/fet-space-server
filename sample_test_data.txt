Sample Data for Fet-Space Server API Testing
===========================================

This file provides sample data for testing the Fet-Space server API routes, using Cameroonian names and context. Use this data in Postman or to seed your database with Prisma. All data reflects the authentication changes (matricule_number for students, email for teachers/admins) and real-time features.

Authentication Endpoints
------------------------

### POST /auth/login
- Student Example:
  - Request Body:
    {
      "identifier": "CMSTU001",
      "password": "student123",
      "role": "Student"
    }
  - Context: "CMSTU001" is the matricule number for a student named Ngono Mbella.
  - Expected User Data: 
    {
      "userId": 1,
      "name": "Ngono Mbella",
      "role": "Student",
      "Students": {
        "matricule_number": "CMSTU001",
        "nationality": "Cameroon",
        "level": "Level 100",
        "institutional_email": "ngono.mbella@ub.ac.cm"
      }
    }

- Teacher Example:
  - Request Body:
    {
      "identifier": "tanyi.nkeng@ub.ac.cm",
      "password": "teacher123",
      "role": "Teacher"
    }
  - Context: "tanyi.nkeng@ub.ac.cm" is the email for a teacher named Tanyi Nkeng.
  - Expected User Data: 
    {
      "userId": 2,
      "name": "Tanyi Nkeng",
      "role": "Teacher",
      "Teachers": {
        "user_id": 2,
        "user": {
          "user_id": 2,
          "name": "Tanyi Nkeng",
          "email": "tanyi.nkeng@ub.ac.cm",
          "role": "Teacher"
        }
      }
    }

- Admin Example:
  - Request Body:
    {
      "identifier": "ekema.tita@admin.cm",

      "userId": 3,

        "user_id": 3,

- POST /auth/refresh
  - Request Body:
    {
      "refreshToken": "Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
    }
  - Context: Use the refreshToken obtained from a successful /auth/login request (e.g., for Ngono Mbella).

Health Check Route
------------------

- GET /health
  - Request: No body or headers required.
  - Context: Verifies server and database health for all users.
  - Expected Response: 
    {
      "status": "healthy",
      "message": "Server and database are running"
    }
  - Error Response: 
    {
      "status": "unhealthy",
      "message": "Server or database error",
      "error": "Database connection failed"
    }

How to Use
----------
1. Seed the Database:
   - Use Prisma Studio or a seed script to insert this sample data into your PostgreSQL database.
   - Example Seed Data:

   - Copy the request bodies and headers into Postman, replacing <accessToken> with tokens obtained from /auth/login.

   - Use a WebSocket client (e.g., Socket.IO Client) to join rooms like 'course_1' and listen for events after triggering actions (e.g., posting an announcement).
